# Ash-Shifa Ruqyah

A Flutter application for prayer reminders, health information, Mom & Child
Care, EasyHome tools, Ruqyah content, and Bazar reminders.

## Requirements

- Flutter stable (the lockfile currently requires Flutter 3.44 or newer)
- Firebase CLI
- FlutterFire CLI
- Firebase project: `ash-shifa-ruqyah`

## Local setup

```bash
flutter pub get
flutterfire configure --project=ash-shifa-ruqyah
flutter run
```

Do not commit service-account JSON files, signing keys, or private API secrets.
The Firebase client configuration generated by FlutterFire is not an Admin SDK
credential.

## Firebase console setup

1. In Authentication → Sign-in method, enable Email/Password.
2. Create a Standard edition Cloud Firestore database.
3. Deploy the repository rules:

   ```bash
   firebase use ash-shifa-ruqyah
   firebase deploy --only firestore:rules,database
   ```

4. Create/login to the account that will seed managed content and copy its UID
   from Authentication → Users.
5. In Firestore, manually create `app_admins/{UID}` with the Boolean field
   `enabled: true`. Firebase Console/Admin SDK must create this marker; app users
   cannot make themselves admin.

The rules intentionally allow guests to read published educational content, so
the app's “Skip to Home” flow does not produce `permission-denied`. Profile and
user-owned data remain private.

## Seed Firestore safely

Seeding is disabled during a normal app start. To create missing managed
documents and repair incomplete ones, run:

```bash
flutter run --dart-define=SEED_FIRESTORE=true
```

Then log in with the enabled admin account. Mom & Child Care creates these six
documents in app order (also stored in `displayOrder`):

1. `problems`
2. `parenting_guide`
3. `smart_tools`
4. `age_based_care`
5. `learning_development`
6. `instant_care`

The default mode creates missing documents and merge-repairs documents that do
not pass the canonical schema/version validation. Complete canonical documents
stay untouched. If an intentional refresh of every managed field is needed,
use merge mode:

```bash
flutter run \
  --dart-define=SEED_FIRESTORE=true \
  --dart-define=MERGE_EXISTING_SEED_DATA=true
```

Both automatic repair and merge mode preserve unrelated existing fields. No
mode deletes documents. Stop the seed build after it succeeds and return to a
normal `flutter run`.

### Seed from GitHub Actions

For a controlled server-side repair, run the manual **Seed Firebase Mom & Child
Care** workflow from the `main` branch. It accepts only the exact project ID,
validates all six bundled documents before connecting, and never runs on a push
or pull request. A repaired document is first copied to
`content_seed_backups`, then its managed fields are merged.

The `firebase-production` GitHub Environment must contain the encrypted secret
`FIREBASE_SERVICE_ACCOUNT_JSON`. Never commit or paste a service-account key in
an issue, pull request, log, or chat. Run with `dry_run: true` first; after the
preview succeeds, rerun with `dry_run: false`. Keep `force_refresh: false` for
the normal repair so already-valid documents remain untouched.

## Data architecture

- Firebase Auth: identity/session
- `users/{uid}`: private profile
- Firestore top-level content collections: admin-managed published content
- `users/{uid}/...`: personal/private app records
- SharedPreferences: device-only checklists and temporary preferences
- Bundled Mom & Child Care content: immediate offline fallback

Mom & Child Care shows its complete bundled snapshot immediately, then checks
Firestore in the background. Only a complete, supported cloud schema replaces
the bundled snapshot; an old or partial cloud document can never blank the UI.
Firestore remains the updateable source of truth and the bundle remains the
verified offline recovery source.
